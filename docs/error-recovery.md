# 原生错误恢复与重试边界 · ACP 0.1.11

本轮采用纯插件策略：AGY 负责原生请求内部恢复；插件将确定的原生终态错误交给 Pi，避免 Pi 再从头重启同一业务回合。它不新增重试引擎、不修改 Pi 宿主或全局设置，也不自动重做已完成工具。

## 三层职责

| 层 | 负责什么 | 不应承担什么 |
| --- | --- | --- |
| AGY 1.5.9 | 原生临时 429、5xx、网络失败的内部重试，以及自身停止条件 | 插件不复刻其次数／退避算法，不承诺所有故障恢复 |
| ACP 插件 | 识别当前 prompt 的确定原生终态，统一 writer 输出失败；原始错误完整保存到同条正文及 diagnostics；失败不推进已接受检查点 | 不将所有异常统称原生终态，不抹掉原文，不伪装成功 |
| Pi 1.5.2 | 历史、会话树、真实工具执行与原有错误处理；用户明确新输入启动新一轮 | 对已确定结束的 ACP 原生失败不再叠加整轮自动重试；其他 provider 保持原有策略 |

原生仍在恢复时不是终态。只在本轮原生错误确已终结、且不属于下表保留路径时规范化。历史轨迹中的旧错误不能使本轮成功变失败；错误步骤也不能变成已接受检查点。

## 统一出口与持久化

优先在插件 `src/message-writer.ts` 的统一失败出口实现，而不是只在宿主 `message_end` 事件改写。普通流与独立摘要 runtime 的 provider 直调都必须覆盖；摘要可能绕过该事件。

对确定的原生终态，向 Pi 提供不包含易触发其重试分类关键词的稳定失败摘要，“AGY 原生调用失败，内部恢复已结束；原始错误见本条消息。”；完整原文放在同条助手正文和 diagnostics 中，保留错误码、服务端消息及已有部分输出。`stopReason` 始终为 `error`，不是 `stop` 或成功。取消仍为原有 `aborted`，不受该规则改写。

普通会话的同条正文用于 UI、Pi 历史和重新打开会话后的可见性；diagnostics 用于定位原始来源。独立摘要调用也返回这两类字段，但 Pi 摘要调用方可能只展示失败摘要，不将内部摘要响应写成主会话消息。单写诊断会使用户丢失错误，单在 UI 添加文字不能保证持久化。不得只去掉 503／429 等关键词然后丢弃原文。

## 错误矩阵

| 输入／状态 | 插件行为 | Pi／用户后续 |
| --- | --- | --- |
| 当前原生 prompt 内部正在重试临时 429／5xx／网络错误 | 等待 AGY 原有恢复与真实终态，不另发 prompt | 用户可按原取消路径中止 |
| 确定原生终态（包括恢复耗尽后的 503、日／账单额度 429、确定的 400 等） | 稳定失败摘要＋同条完整原文＋diagnostics，`error`，不推进接受检查点 | Pi 不叠加本轮整轮重试；保存现有结果，由用户决定下一步 |
| ACP 连接／子进程通信断开、未确定来自原生终态的异常 | 保留原错误及原处理路径，不套稳定摘要 | 仍由现有通信错误处理层处理，不承诺零宿主重试 |
| 上下文超限（如 `context_length_exceeded`） | 保留现有超限错误与分类，仍为失败 | Pi 保留原压缩／溢出路径，不被普通失败摘要遮蔽 |
| 用户取消 | 保留取消及清理路径，`aborted` | 不自动恢复、不改为原生终态失败 |
| 其他 provider 的同类原文错误 | ACP 规则不介入 | 保持宿主已有重试行为 |
| 原生失败前已有工具完成 | 保留真实 toolResult 与配对，不因终态重启而重执 | 明确的新用户输入可正常开启下一轮 |
| `/agy-acp reset` | 用户显式停止执行、清除绑定并保存 reset 标记；Pi 聊天保留 | 下一输入新原生会话，不自动回灌 reset 前全部历史；不是自动重试步骤 |

## 原生重试已知与未知

本轮采用的依据是 **AGY 1.5.9 官方说明与只读二进制证据**，不是新增在线压力测试：

- 已存在临时 429、5xx 和网络错误重试；无需另造引擎。
- 日额度、账单额度，以及已识别的服务端限流等待超过 30 秒时有停止分支。这里是被识别的限流等待阈值，不是所有请求的 30 秒总超时。
- 次数与原生配置有关。旧日志 `attempt 1..5` 仅代表当时样本，不代表硬编码固定五次；没有公开完整控制参数可供本包承诺或设置。
- 原生终态只能说明本次恢复已结束，不能证明账号恢复或服务可用，也不证明封号原因。

用户要求不反复打真实接口或转发端口，不自建正向 TLS 抓包代理。反复请求和代理指纹差异只是重点封号怀疑，未获服务端判因确认。遇 429／403 时先停诊断探针及其自动重试，保存已有错误，按 [safety.md](safety.md) 处理；这不要求擅自删除正常联网所需的既有代理。

## Pi 版本限制与离线验收

此方案依赖 **当前 Pi 1.5.2 的错误文案分类**，不是跨版本公开的重试控制协议。未来分类若改读正文或结构化字段，稳定摘要不一定足够；升级 Pi 后重跑真实 SDK 的离线兼容测试，不宣称永久免疫重试。

Pi 1.5.2 开发兼容参考基线（含 requestIdentity、onPayload 等接缝）归档在 Git tag `archive/handoff-kit-0.1.11` 的 `host-reference/overlay/`。

最终代码验收项：

1. 原生终态 503／额度 429／400：一次 provider 调用、无 Pi 叠加重试；完整原文可见且持久化，stopReason 为 error，事件／快照正确结算。
2. 仅有旧终态标记不足以阻止重试的反例；其他 provider 及 ACP 通信故障保持原路径。
3. 上下文超限、取消、历史旧错误、本轮成功与错误检查点分别验证，不以统一 catch 掩盖失败来源。
4. 工具只执行一次、真实结果保留，用户明确新一轮仍可调用；不用被测输出来构造自身预期。
5. 独立摘要 provider 直调与普通流均覆盖；不能只测 message_end。
6. 全插件离线测试、类型检查及独立解压副本的真实 SDK 零模型装载。不启动 AGY、不读账号认证、不以离线通过冒充服务端恢复。
